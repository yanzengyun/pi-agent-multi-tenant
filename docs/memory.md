# 多用户长期记忆

记忆保存在SQLite的`memories(user_id, content)`，由后端认证用户绑定工具，不接受模型指定用户、文件路径或数据库。每次请求注入自己的完整记忆，总容量8000字符。人物设定、聊天记录和SilverBullet笔记独立保存。

| 工具 | 用途 |
| --- | --- |
| `memory_read` | 返回原文`content`、版本`version`、条目`entries`（`id/content`） |
| `memory_write` | 默认`append`，只传新增内容；后端保留旧原文 |
| `memory_update` | 传刚读取的`id/version/content`，只替换指定段落 |
| `memory_forget` | 用户明确要求遗忘时，传刚读取的`id/version`删除指定段落 |

`memory_write`仅在用户明确要求重写整份记忆时使用`mode: "overwrite"`，同时提供刚读取的`version`。省略模式就是追加，不能靠省略旧内容删除信息。

条目按空行分段，同一段中包含多条事实时，修改应保留未要求变化的事实；只删除其中一项时用`memory_update`保留其余内容。ID是由段落内容及同文出现次序派生的标识，不是跨版本永久主键。修改后重新读取ID和版本；不要自行推测ID。

后端在`BEGIN IMMEDIATE`事务内读取最新内容、校验版本、合并并写入，避免追加使用旧快照覆盖新内容。更新、删除和完整替换都强制校验整份记忆版本，冲突时重新读取。超出8000字符直接拒绝并保留原文，不截断、不自动删除，不自动去重或解决语义矛盾。忘记条目不会删除旧聊天、笔记或历史备份，也没有专用恢复工具。

旧数据不需要迁移，读取与追加不改已有原文。没有新增表、向量模型、定时扫描或后台总结。主账号`pi-memory`插件不受影响。现有`GET /api/memory`仍返回纯文本字段，`PUT /api/memory`仍是用户直接编辑整份记忆的显式替换接口；模型使用上述带版本的专用工具。

示例：

```text
记住，我喜欢简短的中文回答。
再记一条：我正在学习Python。
把学习Python改成学习Rust，其他记忆保留。
忘记我正在学习Rust这件事。
```

验证：`npm test`覆盖旧数据保留、满额不丢数据、按条修改/删除、冲突、双连接和用户隔离。`node scripts/verify-memory-live.mjs /tmp/memory-result.json`使用临时库和合成双用户，验证真实模型追加、修正、遗忘与显式完整替换；需配置SDK/模型和Key，不访问生产库或发送微信，结束清理临时数据。
